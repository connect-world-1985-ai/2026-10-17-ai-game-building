## 1. Hosting and distributing

### 1.1 itch.io (web + download)

- **[Verified-P]** HTML5 games are uploaded as a ZIP containing `index.html` (or a single `.html` file); `.rar/.7z/.tar.gz` unsupported; file names are case-sensitive; use relative paths; external requests must be HTTPS. — https://itch.io/docs/creators/html5 (acc 2026-10-17)
- **[Verified-P]** ZIP limits: ≤ 1,000 files after extraction; path length ≤ 240 chars; ≤ 500 MB total extracted; ≤ 200 MB per single extracted file; UTF-8 names. Staff can lift limits on request. — https://itch.io/docs/creators/html5 (acc 2026-10-17)
- **[Verified-P]** Game is embedded in an `iframe` on itch.io's CDN; default is click-to-play; "Mobile friendly" flag optional; CDN auto-gzips html/js/css/svg/wasm/wav/glb/pck; pre-compressed `.br` / gzip assets are served with the right `content-encoding`. — https://itch.io/docs/creators/html5 (acc 2026-10-17)
- **[Verified-P]** **SharedArrayBuffer**: opt-in checkbox "SharedArrayBuffer support" under *Embed options → Frame options*. It moves the game to a secondary CDN domain (`html.itch.zone`) and sends `COOP: same-origin`, `COEP: require-corp` (HTML pages in the frame use `credentialless` on the itch page). Side-effects: local-storage saves from the old domain are not visible; Firefox originally lacked `credentialless` so itch falls back to launching in a popup. Announcement dated 2 Apr 2022. — https://itch.io/t/2025776/experimental-sharedarraybuffer-support (acc 2026-10-17)
- **[Verified-P]** Godot 4.3 web export added a PWA-based way to get the COOP/COEP headers without server control, because many portals cannot set them. — https://godotengine.org/article/progress-report-web-export-in-4-3/ (acc 2026-10-17)
- **[Verified-P]** If you embed an itch-hosted SAB game in your *own* site, your page must also send COOP/COEP; itch staff recommend linking out instead of embedding. — https://itch.io/t/3288882/cant-embed-into-iframe-sharedarraybuffer (acc 2026-10-17)
- **[Verified-P]** **Revenue share**: "Open Revenue Sharing" — seller chooses 0–100 %; **default 10 %**. Payment processor fee (PayPal/Stripe) is ≈ $0.30 + 2.9 % on top; itch recommends ≥ $2 pricing. — https://itch.io/docs/creators/payments (acc 2026-10-17)
- **[Verified-P]** HTML5 games on itch can only take **donations**; to sell, set kind of game to "Downloadable". — https://itch.io/docs/creators/html5 (acc 2026-10-17)
- **[Verified-P]** Two payout modes: *Direct to you* (you are merchant of record, you handle VAT/chargebacks) vs *Collected by itch.io* (itch is merchant of record, auto VAT, USD only, payout via PayPal/Payoneer, min $5, 7-day hold, staff review 10–14 days typically, tax interview needed). — https://itch.io/docs/creators/payments (acc 2026-10-17)
- **[Verified-P]** Because itch.io is a US company, funds to **non-US entities** have a **default 30 % US withholding** unless you complete the tax interview with a valid tax ID and qualify for a treaty rate. — https://itch.io/docs/creators/payments (acc 2026-10-17)
- **[Practice]** For a German hobbyist: complete the itch tax interview *before* the first sale; check the Germany–US treaty rate and your own German tax obligations with a Steuerberater (not researched here → **Unverified**).

### 1.4 Steam

- **[Verified-P]** **Steam Direct fee: $100 per product**, not refundable, but **recouped in a later payment once the product reaches $1,000 adjusted gross revenue**. Fee cannot be paid with Steam Wallet. — https://partner.steamgames.com/steamdirect (acc 2026-10-17)
- **[Verified-P]** Onboarding: identity/company docs, bank + tax questionnaire (W-9 / W-8BEN-type; verification via third party can take up to 30 days), store page "coming soon" ≥ 2 weeks, review 1–5 days. **Conflict:** the Steam Direct page says a **30-day** wait between paying the fee and release; the Onboarding doc says **21-day**. — https://partner.steamgames.com/steamdirect vs https://partner.steamgames.com/doc/gettingstarted/onboarding (acc 2026-10-17). **[Practice]** plan for 30 days.
- **[Verified-P]** Steam content rules: no content you "don't own or have adequate rights to"; no apps with **advertising-based business models**; no blockchain/NFT apps; adult content must be labelled. — https://partner.steamgames.com/doc/gettingstarted/onboarding (acc 2026-10-17). **[Practice]** An ad-funded portal build (Poki/CrazyGames SDK) cannot be shipped unchanged to Steam.
- **[Verified-S]** **Revenue share 30 % / 25 % / 20 %**: 30 % on the first $10 M of a title's Steam revenue (incl. DLC, in-game sales, Community Marketplace fees), 25 % from $10 M to $50 M, 20 % above $50 M; tiers effective for revenue from 1 Oct 2018. — https://www.gamesindustry.biz/valve-adds-revenue-share-tiers-for-developers ; https://www.theverge.com/2018/11/30/18120577/valve-steam-game-marketplace-revenue-split-new-rules-competition ; Valve announcement (page body not rendered by my fetcher): https://steamcommunity.com/groups/steamworks/announcements/detail/1697191267930157838 (acc 2026-10-17). The Steam Distribution Agreement itself is behind partner login (not read).
- **[Practice]** Steam realistically needs a desktop executable (Electron/NW.js/Godot/Unity export). See 1.6.

### 1.6 Desktop builds, engine exports, code signing

- **[Verified-S]** Electron bundles Chromium+Node (100 MB+ installers, identical rendering); Tauri uses OS webviews (WebView2 on Windows; ~3–10 MB typical) so you must test each webview; Electron/NW.js are the officially supported wrappers for the main Steam bindings (steamworks.js; Greenworks is best-effort); Tauri Steam overlay support is Windows-only and alpha. — https://www.webgamedev.com/publishing/desktop ; https://www.summerengine.com/make-great-games/threejs-game-on-steam ; https://crates.io/crates/tauri-plugin-steamworks (acc 2026-10-17). **[Practice]** For a WebGL/WebGPU game destined for Steam use Electron; for a small itch download Tauri is viable on Windows 11 (WebView2).
- **[Verified-P]** **Godot**: engine is MIT; your game's licence is yours; you must ship the Godot copyright notice + licence text somewhere in docs/credits (a link to godotengine.org/license is acceptable to the Godot team). — https://godotengine.org/license/ (acc 2026-10-17)
- **[Verified-P]** **Unity**: Runtime Fee cancelled 12 Sep 2024; no runtime fee/revenue share for Unity 6 or earlier; Unity Personal free up to **$200,000** revenue+funding (12 months); splash screen optional in Unity 6. — https://unity.com/blog/unity-is-canceling-the-runtime-fee ; https://unity.com/products/pricing-updates ; https://unity.com/legal/editor-terms-of-service/software (acc 2026-10-17)
- **[Verified-P]** **Windows SmartScreen / code signing (Microsoft Learn, 2026)**: an unsigned or newly signed non-Store exe shows a SmartScreen warning until reputation accumulates (by file hash and, for signed files, by publisher cert); **EV certificates no longer bypass SmartScreen (since 2024)**; unsigned files must rebuild reputation on every new hash; Windows 11 **Smart App Control** can block unsigned executables outright. **Azure Artifact Signing** (formerly Trusted Signing) ≈ $9.99/month — but **individual** developers are eligible only in **USA and Canada**; **organisations** in USA, Canada, EU, UK (organisations need 3+ years of verifiable tax history). OV certs ≈ $150–500/year are the fallback for an EU individual. Microsoft Store distribution avoids the warning. — https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation ; https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options ; https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/publish-first-app ; https://learn.microsoft.com/en-us/windows/msix/package/signing-package-overview (acc 2026-10-17)
- **[Practice]** For an EU individual hobbyist: ship via itch/Steam/Microsoft Store (no cert cost), or accept the SmartScreen prompt and tell users ("More info → Run anyway"); buy an OV cert only if distributing a standalone installer widely.

## 2. Asset licences for games

### 2.1 Creative Commons — what each means for a game

Overview of the six licences from Creative Commons: https://creativecommons.org/share-your-work/cclicenses/ **[Verified-P]**. Licence deeds (human-readable): CC BY https://creativecommons.org/licenses/by/4.0/ · CC BY-SA https://creativecommons.org/licenses/by-sa/4.0/ · CC BY-ND https://creativecommons.org/licenses/by-nd/4.0/ · CC BY-NC https://creativecommons.org/licenses/by-nc/4.0/ · CC BY-NC-SA https://creativecommons.org/licenses/by-nc-sa/4.0/ · CC BY-NC-ND https://creativecommons.org/licenses/by-nc-nd/4.0/ · CC0 https://creativecommons.org/publicdomain/zero/1.0/ (deed pages follow the standard CC URL pattern; I fetched the overview and the CC0 deed, not each other deed — acc 2026-10-17).

| Licence | What you may do | Game-specific implication | Label |
|---|---|---|---|
| **CC0** | Copy, modify, distribute, even commercially, no permission; attribution not required; patent/trademark/publicity/privacy rights are **not** cleared; no warranties (https://creativecommons.org/publicdomain/zero/1.0/) | Safest asset licence. Still check provenance (uploader may not own it) and avoid recognisable people/brands. Crediting is courteous (CC recommends it for PD material). | Verified-P |
| **CC BY** | Reuse/adapt, commercial OK, **attribution required** | Fine for commercial games; put credits in a CREDITS file / in-game credits screen and store page. | Verified-P |
| **CC BY-SA** | As BY, but **adaptations must be released under the same or a compatible licence** | If you *modify* an SA sprite/music track and distribute it, the adapted asset must be BY-SA. SA applies only on modification + public sharing; a *collection* may have its own licence but the SA item stays SA (CC FAQ: https://creativecommons.org/faq/). BY-SA 4.0 is one-way compatible with GPLv3. Whether an asset baked into a packed game binary makes the whole game an "adaptation" is not settled in my sources → **[Practice]** avoid SA assets in closed-source commercial games; keep SA assets as separate, unmodified, clearly credited files. | Verified-P (FAQ) / Practice |
| **CC BY-NC** | Non-commercial only; "NonCommercial means not primarily intended for or directed towards commercial advantage or monetary compensation" (CC overview) | **[Practice]** Ads, paid release, paid DLC, or "pay-what-you-want" tips make a game commercial in any prudent reading; avoid NC assets unless the game is truly free/no-ads/no-donation, and even then portal ad revenue (Poki/CrazyGames) is commercial. | Verified-P (definition) / Practice |
| **CC BY-ND** | Distribute only **unadapted**; no derivatives | CC's attribution guide notes that putting ND music behind video/podcast is an *adaptation*; a game that mixes, loops, resizes or recolours an ND asset is an adaptation → ND is generally unusable for game assets. (https://wiki.creativecommons.org/wiki/Best_practices_for_attribution) | Verified-P (guide) / Practice |
| **CC BY-NC-SA / -ND** | Both restrictions | Avoid for commercial releases. | Verified-P |

- **[Verified-P]** CC recommends against using CC licences for **software** but says they are fine for **game art or music** as separate artistic elements. — https://creativecommons.org/faq/ (acc 2026-10-17)
- **[Verified-P]** Attribution in practice = **TASL**: Title, Author, Source (link), License (name + link to deed). "Reasonable" for the medium; credit the name the author chose; crediting a site (e.g. Wikimedia) or "Creative Commons" is **not** enough; if you modified the work, say so; metadata-only/alt-text-only credit is discouraged. Provide a separate credits web page where in-medium credit is awkward. — https://wiki.creativecommons.org/wiki/Best_practices_for_attribution (acc 2026-10-17)
- **[Practice]** AI-generated assets do not carry a CC licence from the model just because the *tool* says so — see §3.6 for Meshy/Tripo.

### 2.2 Fonts, engines, code

- **[Verified-P]** **SIL OFL 1.1**: fonts may be bundled, embedded and **sold with software**; the font itself may not be sold by itself; each copy must carry the copyright notice and licence text; modified versions may not use the Reserved Font Name; fonts and derivatives stay under OFL (documents/games made with the font are not affected). — https://openfontlicense.org/open-font-license-official-text/ (acc 2026-10-17)
- **[Verified-P]** **MIT (Godot)**: only condition is to include the copyright + licence text. See §1.6.
- **[Verified-S]** **GPL**: linking GPL code into your program and distributing it makes the *whole combination* GPL (static or dynamic); data assets that are merely read by a GPL engine are generally separate works with their own licences, but scripts that call the engine's APIs are usually treated as part of the combined work unless the engine has an exception. — FSF FAQ mirror https://www.southampton.ac.uk/~qs2g22/mirror/www.gnu.org/licenses/old-licenses/gpl-2.0-faq-2.html ; discussion https://opensource.stackexchange.com/questions/6253/can-a-video-game-have-a-gpl-licensed-engine-and-gpl-incompatible-licensed-assets/6257 (acc 2026-10-17). (gnu.org returned HTTP 403 to my fetcher, so I used a mirror.)
- **[Practice]** **GPL vs MIT for a game:** MIT/Apache/zlib engines and libraries let you keep your game closed and sell it; GPL libraries force you to publish your game's source under GPL on distribution. If an AI agent proposes a dependency, check its licence *before* adding it (`npm ls`, `licence-checker`) — agents often pick GPL/AGPL packages without saying.

### 2.3 Keeping a CREDITS file (template)

**[Practice]** Keep `CREDITS.md` (and mirror it in an in-game credits screen + store page) with one row per third-party item:

```markdown
| Asset / lib | Author | Source URL | Licence (link) | Changes by us | Bought/AI? | File(s) |
|---|---|---|---|---|---|---|
| "Pixel Frog tileset" | Pixel Frog | https://... | CC0 1.0 https://creativecommons.org/publicdomain/zero/1.0/ | none | downloaded 2026-10-17 | assets/tiles/ |
| Inter font | Rasmus Andersson | https://... | SIL OFL 1.1 | none | — | assets/fonts/ |
| hero.glb | generated with Meshy (Free plan, 2026-10-17) | https://www.meshy.ai | CC BY 4.0 — credit "Model created with Meshy – CC BY 4.0 License" | retextured | AI | assets/models/ |
| Godot Engine | Godot contributors | https://godotengine.org/license/ | MIT | — | — | engine |
```

Also record **date of download and the licence text version** (licences and plans change), and keep a copy of the licence/terms page (PDF or archive link) — especially for AI-tool outputs (plan active at generation time).

## 3. Copyright status of AI-generated assets (and training-data risk)

### 3.1 United States

- **[Verified-P]** **US Copyright Office, *Copyright and AI*, Part 2: Copyrightability (29 Jan 2025).** Conclusions: existing law suffices; AI used to *assist* does not bar protection; copyright covers original human expression even if the work includes AI material; **no copyright for purely AI-generated material or where human control over expressive elements is insufficient**; case-by-case; "**based on the functioning of current generally available technology, prompts do not alone provide sufficient control**"; humans own (a) their works perceptible in AI output, (b) creative selection/coordination/arrangement, (c) creative modifications; no case for new sui generis right. — PDF https://copyright.gov/ai/Copyright-and-Artificial-Intelligence-Part-2-Copyrightability-Report.pdf ; press release https://www.copyright.gov/newsnet/2025/1060.html ; overview https://copyright.gov/AI/ (acc 2026-10-17). Part 3 (training) was released as a pre-publication version on 9 May 2025 (same overview page).
- **[Verified-P]** ***Thaler v. Perlmutter***: D.C. Cir. (March 2025), 130 F.4th 1039 — the Copyright Act requires human authorship; the court noted works made *with the assistance of* AI can still be copyrighted if the author is human. **Cert. denied 2 March 2026 (No. 25-449)**, so the D.C. Cir. rule stands. Thaler disclaimed any human contribution, so the case does not say how much human input suffices. — https://www.scotusblog.com/cases/thaler-v-perlmutter/ (cert denial); https://www.bakerdonelson.com/supreme-court-denies-certiorari-in-thaler-v-perlmutter-ai-cannot-be-an-author-under-the-copyright-act ; https://www.reuters.com/legal/government/us-supreme-court-declines-hear-dispute-over-copyrights-ai-generated-material-2026-03-02/ (acc 2026-10-17). (The exact D.C. Cir. decision date is from the secondary sources/user brief; the opinion itself was not fetched → date **Unverified**.)
- **[Verified-P]** ***Zarya of the Dawn*** (USCO letter, 21 Feb 2023): registration cancelled/reissued — Kashtanova's **text** and the **selection/arrangement** of text and images remain protected; the **Midjourney images are not protected** (not human authorship). — Review Board decision cites it at https://www.copyright.gov/rulings-filings/review-board/docs/Theatre-Dopera-Spatial.pdf ; Reuters https://www.reuters.com/legal/ai-created-images-lose-us-copyrights-test-new-technology-2023-02-22/ (acc 2026-10-17)
- **[Verified-P]** ***Théâtre D'opéra Spatial*** (USCO Review Board, Sept 2023): AI-generated Midjourney image that remains "in substantial form" is "more than de minimis" and must be **disclaimed**; Photoshop touch-ups and upscaling did not rescue it. Allen sued (*Allen v. Perlmutter*, D. Colo. 1:24-cv-02665, filed 26 Sep 2024); **[Verified-S]** summary-judgment briefing complete, no merits ruling as of Aug 2026 (https://thatpainter.com/jason-allen-appeals-copyright-denial-for-prize-winning-ai-generated-work/ — blog, low authority) → status **Unverified**.
- **[Verified-S]** SURYAST (Dec 2023) also refused; CRS summary https://www.congress.gov/crs_external_products/LSB/PDF/LSB10922/LSB10922.7.pdf
- **[Practice] What this means for an agent-built game:** (a) The *game as a whole* usually has protectable human elements (your design, level layouts you author, selection/arrangement, hand edits, human-written text). (b) **Raw AI sprites, textures, music, 3D models and most agent-written code are likely unprotectable by copyright in the US** — anyone may copy those raw outputs; you cannot DMCA them. (c) No source I found addresses *AI-written source code* specifically → **Unverified**; the Part 2 principles (human control over expressive elements) are the best guide. (d) **Document human contribution** (prompts + iterations + your edits, commit history); register only the human-authored parts and **disclose AI content** when registering (Review Board decision).

### 4.1 Steam

- **[Verified-P]** The Steamworks **Content Survey** has a Generative-AI section; it is *not* about efficiency tools but about AI-created content that ships with the game and is consumed by players (artwork, sound, narrative, localization, etc.). Games using live-generated **Adult Only Sexual Content** are not shipped "at this time". Valve says devs are responsible for guardrails; overlay reporting tools; games can be removed. — https://www.gamedeveloper.com/business/valve-tweaks-and-clarifies-ai-disclosure-rules-for-steam (16 Jan 2026) ; https://www.notebookcheck.net/Steam-updates-AI-disclosure-form-requiring-developers-to-report-visible-and-in-game-AI-but-not-background-tools.1206103.0.html (acc 2026-10-17). ### 4.4 EU AI Act Article 50 (transparency) — in force **2 Aug 2026**

- **[Verified-P]** Article 50 text (4 duties): (1) providers of AI systems that interact with people must make that clear **unless obvious** to a reasonably well-informed person; (2) providers of generative systems must mark outputs **machine-readably**; (3) emotion recognition/biometric categorisation notice; (4) **deployers** of deepfake systems must disclose; for "evidently artistic, creative, satirical, fictional or analogous" works disclosure is limited to a form that does not hamper enjoyment; (5) info must be clear at first interaction. "Deployer" excludes AI used "in the course of a **personal non-professional activity**" (Art 3(4)). — https://artificialintelligenceact.eu/article/50/ (mirror of the Regulation text; acc 2026-10-17)
- **[Verified-P]** **Application date and grace period:** Art 50 applies **from 2 Aug 2026**; **Regulation (EU) 2026/1744 (Digital Omnibus on AI), adopted 8 Jul 2026, OJ 24 Jul 2026**, delays *high-risk* rules (to 2 Dec 2027 / 2 Aug 2028) but only gives a **four-month grace period to 2 Dec 2026 for Art 50(2) marking** by generative systems *already on the market before 2 Aug 2026*; no retroactive labelling for earlier content. Fines up to **€15 M or 3 %** of turnover (proportionate for SMEs). — https://eur-lex.europa.eu/eli/reg/2026/1744/oj/eng ; https://digital-strategy.ec.europa.eu/en/faqs/transparency-obligations-under-article-50-ai-act ; https://digital-strategy.ec.europa.eu/en/factpages/quick-facts-transparency-rules-ai-systems (acc 2026-10-17)
- **[Verified-P]** **Commission Guidelines C(2026) 5054 final (20 Jul 2026)** — game-relevant examples (read in the guidelines PDF): (a) interactions with **AI-enabled NPCs in a single-player video game** where it is clear no other person can participate and the AI nature is obvious to all users incl. vulnerable persons → **obviousness exception to Art 50(1)**; (b) **AI-generated fictitious environments (e.g. forests, castles) in video games are not deepfakes**; (c) **real-time content generation that is ephemeral and consumed immediately (e.g. in video games, VR)** may be exempt from *marking* where marking is not technically feasible and users are made aware (in-experience disclosure, session-level notice). Law-firm commentary adds: multiplayer/immersive/realistic contexts (where an NPC might be mistaken for a person), and AI voices/likenesses of **real people**, are not covered by the exemption. — https://ai-act-service-desk.ec.europa.eu/sites/default/files/2026-07/guidelines_on_the_implementation_of_the_transparency_obligations_for_certain_ai_systems_under_article_50_of_the_ai_act_bzptwqhk0ikg1dtlddap41psfy_131215.pdf ; commentary https://www.mishcon.com/news/what-the-eus-final-ai-transparency-guidelines-mean-for-providers-and-deployers ; https://chambers.com/articles/same-npc-different-rules-how-a-player-s-age-changes-their-responsibilities-under-the-ai-act ; https://twobirds.foleon.com/bird-and-bird/reshaping-the-game/final-recommendations (acc 2026-10-17). The guidelines are not binding law (Chambers note).
- **[Practice] Relevance to a hobbyist game:** (1) Using AI **only at development time** → Art 50 duties sit mainly with the **AI tool provider** (marking) and not with you; (2) shipping **an LLM-driven chat NPC or AI-generated images/voices at runtime** → add a visible "AI-generated" notice unless clearly obvious; (3) never use AI to depict **real people/places** realistically without a label; (4) if you are a purely non-professional hobbyist you may fall outside "deployer", but the moment you sell/monetise the game assume you are a deployer/provider → **Unverified** how national regulators treat monetised hobbyists.
- **Germany-specific:** a website offering your game that is not purely private needs a **Impressum** (§5 DDG, formerly TMG, §18 MStV) — also **without** trade registration or profit intent; fine up to €50,000 per Medienanstalt Hessen. — https://medienanstalt-mv.de/medienaufsicht/impressumspflicht/ ; https://www.medienanstalt-hessen.de/aufsicht/telemedien-digitale-dienste-internetaufsicht/impressumspflicht/ ; https://verwaltung.bund.de/leistungsverzeichnis/de/leistung/99000000025492 (acc 2026-10-17) — **Verified-P** (regulators) for the obligation; **Practice** that a hobby game page almost always needs one.

### 5.1 What copyright does and does not protect in games

- **[Verified-P]** ***Tetris Holding v. Xio Interactive*, 863 F. Supp. 2d 394 (D.N.J. 30 May 2012)**: **rules/mechanics are ideas and unprotectable**; but Tetris's **audiovisual expression** (piece shapes/colours/movement, 20×10 field, ghost piece, next-piece display, lock colour change, etc.) is protected; Mino's near-identical "look and feel" **infringed**. Court: "Tetris Holding has given the rules of its game to the public domain, but has kept the rights to its expression." — https://www.govinfo.gov/content/pkg/USCOURTS-njd-3_09-cv-06115/pdf/USCOURTS-njd-3_09-cv-06115-0.pdf (acc 2026-10-17)
- **[Verified-P]** ***Spry Fox v. LOLApps (6waves)***, W.D. Wash., motion-to-dismiss order (Sept 2012): basic match-3 mechanics are not protectable; but **object hierarchy, theme/setting, antagonist and overall expression** plausibly were copied → copyright claim survived (Lanham Act claim dismissed with leave to amend). Settled Oct 2012; **Yeti Town IP transferred to Spry Fox**. Not a final infringement verdict. — https://digitalcommons.law.scu.edu/historical/149 ; https://www.drdocket.com/case/spry-fox-llc-v-lolapps-inc-wawd-2012 ; https://edery.org/2012/10/spry-fox-settlement-with-6waves/ (acc 2026-10-17)
- **[Unverified]** EU position (CJEU *SAS Institute*, C-406/10: functionality of a program/programming language not protected by copyright) — from memory, not re-read here.
- **[Practice] "Inspired-by" mechanics are generally fine; copying the look-and-feel/art/names/levels/audio is where cases are won.** Trade dress, UI layout, level design, character design, sound and music, and specific *selection and arrangement* of game objects are what to change.

### 5.2 Nintendo and fan-game enforcement history

- **[Verified-S]** Nintendo has repeatedly used DMCA takedowns on fan games that use its characters/names/locations: Super Mario 64 HD (2015), **AM2R** (Aug 2016, days after release), **Pokémon Uranium** (Aug 2016, after 1.5 M downloads; creators pulled downloads), Pokémon Prism (Dec 2016, days before release), Game Jolt purge of **500+ fan games** (Sep 2016), a 379-game Game Jolt DMCA wave (2021), Metroid Prime 2D (Aug 2021). — https://arstechnica.com/gaming/2016/09/nintendos-dmca-backed-quest-against-online-fangames/ ; https://www.polygon.com/2016/8/14/12472616/pokemon-uranium-taken-down-nintendo/ ; https://en.m.wikipedia.org/wiki/Nintendo_and_fan_games (acc 2026-10-17). 2021 and Metroid Prime 2D items are Wikipedia-only → **Unverified** detail.
- **[Verified-S]** **Super Mario 64 PC port (May 2020)**: Nintendo's lawyers (Wildwood Law Group) used DMCA notices against a **precompiled PC executable** and gameplay video ("unauthorized derivative work"), but **not** the public `n64decomp/sm64` decompilation repo, which contains no assets and requires the user's own ROM. — https://www.videogameschronicle.com/news/nintendo-takes-action-against-mario-64-pc-port/ ; https://www.eurogamer.net/nintendo-faces-an-uphill-struggle-trying-to-scrub-the-unofficial-super-mario-64-pc-port-from-the-internet ; https://github.com/n64decomp/sm64 (acc 2026-10-17)
- **[Verified-P/S]** **Yuzu** (Switch emulator): Nintendo v. Tropic Haze settled for **$2.4 M**; court order (6 Mar 2024) enjoined distribution, source sharing, circumvention tools, and domain. Circumvention case (DMCA §1201), not clone case, but shows posture. — https://storage.courtlistener.com/recap/gov.uscourts.rid.56980/gov.uscourts.rid.56980.11.0.pdf ; https://www.theverge.com/2024/3/6/24092680/yuzus-2-4m-settlement-with-nintendo-has-been-approved-by-a-judge (acc 2026-10-17)
- **[Verified-S]** **Palworld (Pocketpair)**: Nintendo + The Pokémon Company sued in **Tokyo District Court on 18 Sep 2024** for **patent** infringement (three Japanese patents on game mechanics: JP 7545191, 7493117, 7528390 per a secondary summary) — **not** a character-copyright suit. Pocketpair denies infringement but changed features (Pal Sphere summon, gliding) as precaution. Claims narrowed Nov 2025 to older versions. Case **pending**; reports say an evidence hearing was held **1 Oct 2026** and the court's preliminary view is expected **9 Nov 2026**. Separately, the **JPO refused** a related touchscreen monster-capture application (**No. 2026-019762**) on **7 Jul 2026** (obviousness; refusal does not invalidate the asserted patents); Nintendo/Pokémon Company filed an appeal trial request around 3 Sep 2026. — https://intellectual-property-helpdesk.ec.europa.eu/news-events/news/jpo-refuses-nintendos-touchscreen-monster-capture-patent-application-eu-trade-mark-dispute-go-vege-2026-08-07_en (**Verified-P-ish**: EU IP Helpdesk) ; https://toyokeizai.net/articles/-/961232?page=2 ; https://drezzed.clownfishtv.com/p/nintendo-and-palworld-go-back-to ; https://oncorlawsuit.com/palworld-lawsuit/ ; https://www.oricon.co.jp/article/3374628/ (acc 2026-10-17). The Oct 1 / Nov 9 dates, the USPTO non-final rejection (Apr 2026), the "~$30k" damages estimate and the "1.0 on 10 Jul 2026" release date come from low-authority blogs → **Unverified**. **Conflict** between sources on whether the Oct 1 session took place (one aggregator says it could not confirm) — see §8.
- **[Practice] Lesson from Palworld:** (a) **mechanics can be patented** (in Japan/US/EU) even though they're not copyrightable — large rights-holders can sue on narrowly claimed mechanisms (e.g. "throw a ball to summon a creature while ...") even when art is original; (b) the realistic risk to a hobbyist is a **takedown notice** from a portal/store, which is cheap for the rights-holder and costly for you.

### 5.3 Trademark and naming

- **[Verified-P]** Platform rules: Apple 4.1(a) "don't simply copy the latest popular app … or make minor changes to another app's name or UI", 4.1(c) no other developer's icon/brand/product name, 5.2.1 no unlicensed trademarks/copyrighted works/"copycat representations, names, or metadata" (https://developer.apple.com/app-store/review/guidelines/ ; https://apple-docs.everest.mt/docs/app-store-review/5.2/). Steam: content you "don't own or have adequate rights to" is prohibited; Valve has DMCA and **trademark complaint** forms (contentsurvey FAQ). Newgrounds: no Mario/Angry Birds sprites. Roblox: removes content on valid copyright/trademark requests and may proactively delete suspected infringing assets (https://about.roblox.com/community-standards). All **Verified-P**.
- **[Verified-S]** Name-fight precedents: **Mojang v Bethesda ("Scrolls")** settled Mar 2012 — Bethesda/ZeniMax kept the mark, licensed it to Mojang for the existing card game only, barred for any sequel/other game (https://www.theverge.com/2012/3/10/2860164/mojang-bethesda-scrolls-trademark-dispute); **King v Stoic ("Saga") and CandySwipe ("Candy")** — King's "candy" mark approved by USPTO 15 Jan 2014, then disputes settled (https://www.pcmag.com/news/king-settles-fights-with-banner-saga-candyswipe-developers). (acc 2026-10-17)
- **[Verified-P]** Clearance tools: USPTO "comprehensive clearance search" guidance (https://www.uspto.gov/trademarks/search/comprehensive-clearance-search-similar-trademarks), **TMview** free multi-office search (https://www.euipn.org/en/tools/TMview), EUIPO **Early TM Screening** (https://www.euipo.europa.eu/en/news/euipo-launches-new-ai-powered-tool-to-screen-trade-marks-before-filing). EUIPO tool is non-exhaustive. (acc 2026-10-17)
- **[Unverified]** Claims about particular suffixes ("-craft", "-man", "Super …") being risky: **not researched**; my advice is to run a TMview/USPTO search on the *exact* proposed title in the game/software classes (Nice 9, 41, 28) before committing to art, domain and store page.
- **[Practice]** **Naming checklist:** no franchise names (Mario, Pokémon, Zelda, Minecraft, etc.), no "-like" marketing that uses their marks, no look-alike logo/colour trade dress; coin a distinctive title; search domains + app stores + TMview + USPTO + common-law web search; avoid asking an AI to "make a Mario-style plumber" because the output may reproduce protected character designs (the *Disney v Midjourney* case in §3.5 is about exactly this).

### 5.4 Practical guidance — "clone-safe" design

1. **Original characters, world, names, UI, music and levels.** Zero Nintendo/Sega/Capcom sprites, level layouts, sound effects, fonts, ROM-derived assets.
2. **Mechanics inspiration is OK** (platformer jumps, match-3 rules, Tetris-style falling blocks) — but change *expression*: shapes, grid size, theme, hierarchy of objects, feedback effects (Tetris v Xio; Spry Fox).
3. **Avoid "gap-filler" cloning of a single hit** (Triple Town/Yeti Town) — re-skinning someone's progression system and economy numbers is what got Yeti Town into trouble.
4. **Don't ask AI to imitate** named IP; reject outputs that look familiar; do a reverse-image search on key art.
5. **Patents**: if your core loop is a very specific known mechanism by a litigious company (summon/capture/combat flow), consider a quick patent search (Google Patents / J-PlatPat / Espacenet) — **Unverified** that this is cost-effective for hobby scale.
6. **Fan games**: assume takedown; do not monetise; never publish a binary containing Nintendo assets; legal "decompilation + user-supplied ROM" projects are a grey area at best.

## 6. Practical checklist — hobbyist publishing an agent-built game with AI + free assets

**A. Before you build**
- [ ] Choose engine/stack with a permissive licence (Godot MIT, Phaser/Three.js MIT, Unity Personal ≤ $200k) — §1.6/2.2.
- [ ] Make a `LICENSES/` + `CREDITS.md` from day one (template in §2.3). Tell your coding agent in its project rules to **record the licence of every dependency/asset it adds** and to refuse GPL/AGPL/NC/ND additions without asking.
- [ ] Decide the **asset policy**: CC0 / paid / own-made first; CC BY second; **no NC/ND/SA** in a commercial game.

**B. While building**
- [ ] **Log human creative contribution**: design notes, hand-drawn/edited assets, iterations (supports copyright for human parts — §3.1; Chinese courts want process records — §3.4).
- [ ] For AI-generated assets: note **tool, plan (free/paid), date, prompt, output licence terms** (Meshy/Tripo free-tier traps — §3.6).
- [ ] Prefer **paid-tier** generators if you may sell; check Midjourney's $1 M rule / Stability's $1 M rule.
- [ ] Don't prompt with franchise/artist names; review outputs for lookalikes; keep Nintendo/Disney/Pokémon motifs out.
- [ ] If the game calls an LLM/image model **at runtime**: add moderation/guardrails, report button, "AI-generated" notice (Steam live-generated, Google Play, Roblox, EU Art 50 — §4).
- [ ] No ads on Steam builds; no IAP on Poki; no external links on Poki without SDK; check portal rules (§1.3, §1.4).

**C. Before release**
- [ ] **Trademark/name check** (TMview, USPTO, stores, domains); avoid anything "-like" with a famous mark (§5.3).
- [ ] **Licence audit**: every asset in `CREDITS.md`, attribution visible in-game + store page (TASL, §2.1); include MIT/OFL notices (Godot, fonts).
- [ ] **AI disclosure** where required: itch.io AI field; Steam content survey (pre-generated art/audio/text/store art; live-generated); Newgrounds art rules.
- [ ] **Hosting**: for web build — itch.io (SAB checkbox if Godot threads), or Cloudflare Pages (25 MiB/file) / GitHub Pages (non-commercial) — watch bandwidth caps (§1.2).
- [ ] **Desktop build**: Electron (Steam) or Tauri/Godot/Unity export; sign if possible; on Windows 11 expect SmartScreen prompts for new/unsigned binaries; consider Microsoft Store (free for new individual accounts, 12 % for games).
- [ ] **Money & tax**: itch tax interview (30 % default withholding for non-US without TIN); Steam $100/app + tax docs + 30-day wait; consider a Steuerberater; **Impressum** on your own site (§4.4); privacy policy if you collect analytics/crash logs (GDPR — not researched here).
- [ ] **Age rating / content**: Steam survey auto-generates regional ratings; mobile stores have rating questionnaires (not researched in depth).

**D. After release**
- [ ] Respond quickly to takedown notices (DMCA / store trademark complaints); keep `CREDITS.md` and receipts for provenance.
- [ ] Re-check ToS of AI tools yearly; re-read Steam/itch AI policy before each major update.
- [ ] Don't claim "100 % hand-made"/"human-generated" if AI was used (OpenAI ToS forbids representing output as human-made; Steam/itch disclosure rules).
