## 0. One-paragraph summary (what an agent can really do)

1. A coding agent can call a hosted image model through a plain REST call, an SDK, a CLI, or an MCP server, and drop PNG files into the project. The easiest/most general models today are OpenAI GPT Image (2 / 2.5), Google "Nano Banana" (Gemini image models), FLUX 3 / FLUX.2 (Black Forest Labs), Ideogram 4.x/4.5, Recraft V4.x (the only one with **native SVG** output), and aggregators (fal.ai, Replicate, Scenario, Layer) that wrap hundreds of models.
2. **Transparency is the first trap.** Native alpha is available from OpenAI GPT Image (preview flag), Ideogram (4.5 `background: transparent` + dedicated transparent endpoints), PixelLab and Retro Diffusion (pixel-art tools), Recraft (remove-background / vector). Google's Nano Banana models do **not** output alpha (reported by several practitioners; Google docs say nothing about alpha) — use chroma-key or a "white-vs-black difference matte".
3. **Animation consistency is the second, bigger trap.** Frame-by-frame image generation drifts (identity, scale, palette, foot placement). Everyone who shipped something reports the same fix: use a game-specific tool with a skeleton/animation model (PixelLab, Retro Diffusion animations, Ludo.ai), or generate a short video and extract frames, then run deterministic post-processing (trim, anchor, palette snap, pack).
4. **Pixel art from general models is "fake pixel art"** (non-uniform grid, too many colours). Fix with grid-snapping/quantising tools (proper-pixel-art, unfake.js, spritefusion-pixel-snapper) or use pixel-native generators (PixelLab, Retro Diffusion).
5. Without any image model, an LLM can still produce SVG, Canvas/WebGL code, GLSL shaders, palette-index pixel grids, procedural textures. Quality is good for geometric/icon/UI work and poor for organic characters/anatomy; there is a mature "pelican on a bicycle" informal benchmark and several 2025–2026 academic SVG benchmarks.

### 1.2 Notes per service (details worth knowing)

**OpenAI GPT Image 2.5 / 2 (Verified)**
- Official guide says: "set `background: "transparent"` and use `output_format: "png"` or `"webp"`" for transparent output "with either model" (Sunburst/Flare). Source: https://developers.openai.com/api/docs/guides/image-generation (accessed 2026-10-17).
- OpenAI's own limitation list (same page): latency "up to 2 minutes"; text placement "can still struggle"; **consistency: "may occasionally struggle to maintain visual consistency for recurring characters … across multiple generations"**; composition/layout control is imperfect. This is the vendor itself confirming the sprite-consistency problem.
- Cached-input rates only apply to the Responses API image tool, not direct Images API / `/edits`.
- Per-image price: OpenAI says use its calculator; the primary page gives no static table for 2/2.5. The only "per image" numbers I found are secondary (Magica: $0.006 / $0.053 / $0.211 for low/medium/high 1024×1024 on gpt-image-2). **Practice/Unverified.**
- Rate limits: a secondary source says Tier 1 = 5 images/min, Tier 5 = 250 (Unverified).

**Google Nano Banana family (Verified for prices; alpha = Practice)**
- Pricing page notes image output at **$30 per 1M tokens** for 2.1; 1K = 1,120 tokens, 2K = 1,680, 4K = 3,780. For Gemini 3.1 Flash Image the rate is $60/1M (747 / 1,120 / 1,680 / 2,520 tokens).
- The docs state "All generated images include a SynthID watermark." (invisible watermark; no effect on gameplay, but good to know).
- Multi-turn conversational editing relies on "Thought Signatures"; Nano Banana 2 Lite is "not optimized for multiple reference inputs or multi-turn sequential editing" (docs).
- No native alpha: three independent sources (Robotic Ape blog 2026-03-07, Phil Schmid, a Medium author, plus an MCP skill README) all say it returns flat RGB. See §2.2.

**Recraft (Verified)**
- Only major API found with first-class **vector (SVG)** generation (`/images/generations/vector`), with prices $0.05–$0.08 per vector image, plus **Vectorize PNG→SVG at $0.01** and **Remove background at $0.01**. SVG URLs valid ~24 h. Source: https://www.recraft.ai/docs/api-reference/introduction (2026-10-17).
- Good for: icons, UI glyphs, logos, flat 2D props that must scale. Not a character-animation tool.
- ToS 6.2: you own API assets; **may not be used to train AI models**.

**Ideogram (Verified)**
- Both a general model (4.5, with `background:"transparent"`) and dedicated transparent endpoints (4.0/3.0 "Transparent") — transparent endpoints at 1K cost $0.03 (Turbo) / $0.06 (Default) / $0.10 (Quality).
- `dry_run:true` returns a PriceQuote without billing — handy for an agent.

**Midjourney (Verified/Practice)** — no official API; do not build an agent pipeline on third-party wrappers (ToS risk).

**Stability (Verified)** — still available, cheap ($0.025–$0.08), but not a leading model in Oct 2026; relevant mainly because **SD/SDXL ecosystem tooling** (ControlNet, LoRA, LayerDiffuse, ComfyUI) is mature and local.

## 2. The hard problems and the known techniques

### 2.1 Character / style consistency

### 2.2 Transparent backgrounds

| Approach | Tools | Notes | Label |
|---|---|---|---|
| **Native alpha from the model** | OpenAI `background:"transparent"` (PNG/WebP; **JPEG cannot**); Ideogram 4.5 `background:"transparent"` and `…-transparent` endpoints; PixelLab `no_background` / transparent options; Recraft vector | OpenAI cookbook: describe "isolated subject on a fully transparent background", avoid "checkerboard", repeat "preserve the transparent background" in each edit prompt | Verified (OpenAI cookbook, Ideogram docs, PixelLab docs) |
| **Generate on flat chroma colour + key it out** | Prompt for exact `#00FF00` (or magenta), 2–3 px white outline, "no green on subject", then **HSV** threshold (reported working tolerances: hue ±22° around 120°, saturation ≥ 0.3, value ≥ 0.3), light edge softening, zero colour of fully transparent pixels | Reported by Robotic Ape (2026-03-07, Nano Banana Pro) and Phil Schmid; a dog-game blog reports **magenta** worked after green failed on fur-coloured contrast | Practice |
| **Difference matting (white vs black render)** | Generate subject on white, then *edit* the same image to a black background, compute alpha from the pair (alpha = 1 − ‖pixelW − pixelB‖ / ‖white − black‖); preserves glass/shadows/soft edges; **must use edit mode, not regeneration** (else halos) | `bdog720/diff-matting-skill` (1 star); a Medium post gives a TypeScript+`sharp` implementation | Practice (the maths is sound; skill repo is tiny) |
| **Segmentation / background removal models** | **rembg** (25,103 stars, MIT, last push 2026-10-10); **BiRefNet** (4,294 stars, MIT, last push 2026-10-11 — weights also MIT); BRIA RMBG-2.0 (**CC BY-NC 4.0 weights; commercial needs a BRIA agreement or their API**; fal endpoint $0.018/img, $0.03 with prompt); Recraft remove-background $0.01; PixelLab pixel-art bg remove ~$0.0055; Scenario `photoroom-background-remover`; remove.bg (pricing page was JS-only; one secondary comparison says ~$1 per full-res image PAYG — **Unverified**) | For game sprites BiRefNet is the best licence-clean local option; segmentation models can eat thin parts (weapons, hair) and can't fix baked-in anti-aliasing against a background colour | Verified (GitHub API, licence files, fal page) |
| Why not "prompt for transparent" on models without alpha | Models paint a checkerboard/white/black/grey background as pixels | "You cannot cleanly remove a background that shares color space with your sprite content (black bg + black outlines = unsolvable). | **Layer-aware diffusion (LayerDiffuse)** | SD/SDXL-era local models that output RGBA | `lllyasviel/LayerDiffuse` 2,224 stars Apache-2.0 (last push 2024-06-16); `huchenlei/ComfyUI-layerdiffuse` 1,770 stars Apache-2.0 (2025-02-25). Older stack; not updated this year | Verified (GitHub) |
| **Validate on contrasting backgrounds** | Render every sprite over grey, green, and an alpha heat-map; "Those moody, dim backdrops look gorgeous, and they lie to you." | Real-world post-mortem from a Claude+Gemini dog game | Practice | https://varund.com/blog/a-game-starring-my-dog/ |

Conflicting-info flag C1: Cloudflare's model page for `openai/gpt-image-2` says "transparent backgrounds are not supported — use `openai/gpt-image-1.5` for transparent PNGs", while OpenAI's own guide/cookbook says transparency is supported in preview (gpt-image-2) and on 2.5. Probably a wrapper (Cloudflare) lagging the OpenAI change on 2026-08-20; **go with OpenAI's primary docs, but have the agent verify alpha on the actual PNG** (`PIL.Image.getbands()` contains `A` and min alpha < 255).

### 2.3 Animation frames and sprite sheets

**What goes wrong (all Practice, many independent sources)**
- Independent per-frame generation → hair colour, dress pattern, proportions change each frame. (changeinmotion.tech, 2026.)
- "Image models cannot follow strict rules": sprite sheets need a rigid grid and a character centred/anchored in each cell; models misalign, bleed neighbouring frames, and don't understand leg motion (Layr Kits guide; Gamelabs Studio; a YouTube workflow video on "frame drift").
- Dev.to post-mortem: the author **gave up on AI characters and switched to CC0 hand-drawn sprites** ("Making game assets with AI isn't viable for character animation yet"), while keeping AI for code and procedural VFX.
- Sources: https://changeinmotion.tech/blog/2026/animating-pixel-art-game-character-ai-when-generation-isnt-answer/ ; https://www.layrkits.com/guides/sprite-sheet ; https://gamelabstudio.co/blog/why-ai-cant-make-game-ready-spritesheets ; https://dev.to/junhee916/what-i-learned-trying-to-make-a-game-with-ai-only-half-the-truth-about-claude-for-game-dev-3j2p ; https://www.youtube.com/watch?v=nIAIxvNUrdU.

**Known working approaches**
1. **Game-specific animation engines** (best first stop): PixelLab skeleton/text animation + 4/8-direction rotations (Verified endpoints); Retro Diffusion animation styles ($0.07–$0.25); Ludo.ai sprite animation from a single image (Forge Pixel for low-res pixel art, 1.5 credits/s). PixelLab's v3 skeleton mode "moves the character instead of redrawing it each frame — steadier identity and colours" (MCP docs).
2. **Generate a short video of the character on a chroma background, then extract frames** (one practitioner used an image-to-video model; process: green-screen clip → `ffmpeg` → PIL/NumPy → sprite sheet; "Consistency beats resolution"; "Do not crop each frame separately — keep one canvas"). Layr Kits recommends 12–24 frames and first creating a "transition pose" first-frame image for simple sprites. (Practice.)
3. **Row-per-state with an identity lock + deterministic extraction** — implemented in open-source agent skills:
   - `aldegad/sprite-gen` (2,860 stars, Apache-2.0, pushed 2026-10-17): Codex/Claude skill + Python CLI: one base image → per-state rows → chroma alpha → connected-component frame extraction → atlas + `manifest.json.frame_layout`; plus a curation web view ("Generation gets you 90%"). Source: https://github.com/aldegad/sprite-gen.
   - `0x0funky/agent-sprite-forge` (4,485 stars, MIT, pushed 2026-10-06; fork `joeyjoker/agent-sprite-forge` 2 stars works with any agent): GPT Image-driven skills `generate2dsprite`, `generate2dmap`, exports for Godot/Unity. Source: https://github.com/joeyjoker/agent-sprite-forge (fork) — star count is for the upstream.
   - `ianlintner/ai-pixel-art-image-generation` (22 stars, MIT): Claude Code skill on `gpt-image-2` + nearest-neighbour downscale + named-palette quantise, Gemini for reference-based frame consistency, **Tiled TSX/TMJ** export, QA report. Source: https://github.com/ianlintner/ai-pixel-art-image-generation.
4. **Human curation step**: drop frames that don't fit; "you don't need all of them" for walk cycles (YouTube workflow). Agents can't see subtle jitter reliably → numeric checks (sprite-canon) or side-by-side contact sheets.

### 2.5 Tileable / seamless textures and PBR maps

- **Tilesets**: PixelLab has top-down (Wang-style, "two terrain levels"), side-scroller platform and isometric tile endpoints (16×16 tiles ~ $0.0079); Retro Diffusion tilesets $0.10 / single-tile styles $0.06; `ianlintner/ai-pixel-art-image-generation` makes N seamless tiles + TSX. (Verified for PixelLab/RD prices.)
- **Seamless textures from general models**: no vendor in this research documents a guaranteed "tileable" flag for GPT/Gemini/FLUX; reports say to generate then make seamless in post (offset-and-heal, wrap-around edge blend). **Unverified** that any hosted general model guarantees tiling. Tools that do the post step: `TahriT/TotallyNormal` (browser, 7 stars, licence not detected, "Commercial Open Source"/non-commercial per README snippet), `qornflex/ComfyUI-QFX-PBRGenerator` (7 stars, Apache-2.0: BaseColor/Normal/Roughness/Metallic/AO/Height, seamless modes `off/seamless/mirror/replicate`, Marigold-based delighting), `gutierrezmigueljeronimo/MatForge-App` (1 star, Apache-2.0 per README; Normal/Roughness/Metallic from RGB, "Make Tileable", PVT-v2 model trained on MatSynth; reported MAE normal 10.37°), `lovisdotio/fal-texture-pbr-generator` (26 stars; calls fal "PATINA" for PBR maps from text/image). All are **small/new repos → Practice, not established standards.**
- **Normal maps for 2D sprites**: PixelLab's `/v2/normal-map` is a vendor endpoint ($0.0065 at 92×92) (Verified). SpriteIlluminator (CodeAndWeb) is a paid desktop alternative (bundle prices on the TexturePacker page) (Verified bundle prices; product capability not read).
- **PBR maps for 3D**: Scenario advertises 3D meshes with PBR textures; Layer's estimate API has `pbr_materials` option for 3D (Verified in docs read; quality not assessed). Out of R1 scope — see R2 (3D).
- Flat-sprite lighting caveat from a practitioner: "Flat 2D sprites have no normal maps, so a physically 'correct' light does almost nothing to them" — needed ~10× tuning and luminance probing (Practice). Source: https://varund.com/blog/a-game-starring-my-dog/.

## 4. What a language model can draw with no image model

### 4.1 What works / what doesn't (Practice unless noted)

| Output type | Typical quality | Good for | Evidence |
|---|---|---|---|
| **SVG** (vector shapes) | Frontier models now produce recognisable animals/objects; fine for icons, UI, simple props | Icons, flat UI, particle shapes, logos, simple backgrounds | Willison pelican series (below); VectorGym / SVGenius benchmarks |
| **Canvas / WebGL / Three.js / p5.js code** (procedural drawing) | Reliable for geometric/abstract visuals, particles, parallax backgrounds | Placeholder art, VFX, procedural levels | general practice |
| **GLSL / fragment shaders** | Harder: ShaderMatch (ICSE LLM4Code 2025) — 467 Shadertoy function-completion tasks; "even top models fail to generate working code in 31% of cases" (2025 models) | Water, fire, glow, post-processing | Verified (paper abstract) |
| **Pixel art as arrays / palette-index grids** | Pixel Art Bench (24×24, palette of 2–10 hex + string-rows grid, LLM-judge Elo): works as a task; small models fail; fine-tuning improves format but "fails to produce meaningful improvements in pixel art quality" | Tiny icons, tiles, 16×16–32×32 sprites | Verified (benchmark pages read) |
| **LLM → drawing commands → rasteriser** (rectangles, circles, polygons, flood fill) | AssetForge experiment with Claude: "hit-or-miss, especially complex anatomy"; judge on rendered pixels not code intent | Items, vehicles, terrain at 32–64 px | Practice (single-author blog) |
| **Procedural textures / noise (Perlin etc.), tilemaps, dungeon generation** | Strong — it's ordinary code | Seamless tiles, terrain, caves | Practice |

### 4.2 Notable evidence on LLM SVG quality

- **Simon Willison's "Generate an SVG of a pelican riding a bicycle"** (benchmark started Oct 2024): by Oct 2026 he writes the correlation with model quality is "mostly severed" and says "don't go using pelicans to compare models" (quoted via Hugging Face OpenEnv page, which also quotes the Kimi K3 post). Recent examples on his tag page: Gemini 4 Argon ("Gemini has a track record of producing great SVGs, and are the only lab where I know their staff have invested in SVG specifically"), Meta Muse models, Claude Sonnet/Opus 5.5 ("max" effort pelican ran 128,000 tokens at ~$1.28 then failed to produce an SVG), GPT-6 Astra "much better" than GPT-5.6 Sol. **Verified (his tag page read) / secondary for the quotes inside DEV post.** Sources: https://simonwillison.net/tags/pelican-riding-a-bicycle/ ; https://huggingface.co/docs/openenv/environments/pelican_svg ; https://dev.to/_94be737e156beb4d74df2/two-years-of-pelicans-on-bicycles-103-svgs-66-models-and-what-the-guy-who-invented-the-benchmark-4c7e.
- **Hugging Face OpenEnv "Pelican SVG Environment"** (a scored version): on the canonical task, **136 of 139 samples from 7 frontier models scored 1.000 on the structural layer and 47 scored 1.000 overall → "It is saturated."** Judge-dependence: same drawing scored 0.639 vs 0.875 under two different judge models. **Verified (page read).**
- **"Are AI labs pelicanmaxxing?"** (Dylan Castillo): 1,008 SVGs, 7 frontier models, LLM judge; found **no significant pelican-on-bicycle-specific boost** (largest GLM-5.2 +0.35, p = 0.12), and suggests Google/DeepMind-style "SVGmaxxing" in general rather than pelican-specific. **Practice (single author, LLM-as-judge).** https://dylancastillo.co/posts/pelicanmaxxing.html
- **Academic SVG benchmarks (Verified, abstracts/pages read):**
  - SVGenius — arXiv:2506.03139 (submitted 2025-06-03): 2,377 queries, 24 domains, 22 models; "proprietary models significantly outperform open-source … all models degrade with complexity … reasoning-enhanced training more effective than pure scaling … style transfer remains the most challenging".
  - VectorGym — arXiv:2603.29852: text→SVG, sketch→SVG, editing, captioning; reported "GPT-5.1 leads Text2SVG (93.00 VLM-judge); Gemini 3 Pro leads overall (73.17)" (per search summary of the paper; table not independently checked → Practice).
  - SVGEval — arXiv:2608.01977; SVG-Score — arXiv:2609.03806 (human-aligned evaluation, 16 generators) — both about *evaluation*, not new rankings.
  - Earlier datasets: VGBench (Zou et al. 2024, arXiv:2407.10972), SVGBench/SVG-Stack, UniSVG (525k).
- Take-away for the tutorial: **LLM-written SVG is genuinely usable for simple game UI/icons**, benchmark scores are saturating on easy prompts, but this is **not** evidence that LLMs can draw consistent animated characters.

## 6. Top 10 headline facts

1. **OpenAI's current image models are `gpt-image-2.5-sunburst` and `gpt-image-2.5-flare`; token-priced at $30 per 1M image-output tokens, with native transparent PNG/WebP via `background:"transparent"`** (and OpenAI's own docs list recurring-character consistency as a known limitation). — https://developers.openai.com/api/docs/guides/image-generation ; https://platform.openai.com/docs/pricing (2026-10-17)
2. **Google's Nano Banana 2.1 costs $0.0336 / $0.0504 / $0.113 per 1K/2K/4K image (batch half), Nano Banana 2 Lite $0.0336 per 1K, Nano Banana Pro $0.134 (1K/2K) – $0.24 (4K); Imagen 4 was shut down 2026-08-17 and Nano Banana (2.5) was due to shut down 2026-10-02.** Gemini images do not carry alpha. — https://ai.google.dev/gemini-api/docs/pricing ; https://ai.google.dev/gemini-api/docs/deprecations

## 7. Open questions / conflicts

**Conflicts between sources**
- **C1 — GPT Image 2 transparency.** OpenAI cookbook/guide: supported (preview; shipped 2026-08-20 per a secondary source). Cloudflare model page: "transparent backgrounds are not supported — use gpt-image-1.5". Likely a lag in Cloudflare's wrapper. Verify on the real PNG.
- **C2 — Which Gemini model is the "recommended replacement" for Imagen 4.** One fetch of Google's deprecations page names `gemini-3.1-flash-image`, another fetch names `gemini-nano-banana-2.1` (different cache dates). The image-generation doc says "Recommended for all new projects to use Nano Banana 2.1".
- **C3 — FLUX 3 Image price.** bfl.ai/pricing calculator showed "$0.048 / image" at an unclear default resolution; docs.bfl.ai price cells were blank in the fetch; fal lists $0.048 **per megapixel**; Runware lists $0.048 for a 1360×768 text-to-image. Needs a live check; treat $0.048 as "roughly 5 cents for ~1 MP".
- **C4 — Retro Diffusion price floor.** Official api-examples README: RD Fast ~$0.03; the hosted MCP README says "from ~$0.015 (RD Fast)" / "from ~$0.01 per image"; a third-party skill documents $0.015–0.04 size-dependent. Use `check_cost:true`.
- **C5 — FLUX 3 Image Klein commercial use.** The Hugging Face licence says commercial *output generation* is allowed for "Qualifying Users" (< US$5M revenue), but BFL's model page FAQ says "Running Klein in a product needs a commercial licence". These are not obviously the same scenario (generating outputs vs running the model in a product); the tutorial should say "read the licence".

- **C8 — Star counts reported by search tool vs `gh api`**: shinpr/mcp-image 172 (search) vs 178 (`gh`); use `gh` numbers above. ConechoAI/Nano-Banana-MCP: `gh` call returned nothing (rate/timeout) → count unverified.
