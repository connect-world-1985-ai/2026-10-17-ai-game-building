Hands-on: five starter projects

Five small projects in learning order, each with a ready-to-copy prompt for a coding agent (Cursor, Claude Code, Codex or similar), a "done when" list, and a stretch goal. Each teaches one idea from this site, and none needs paid services.

How to use these prompts

Start each project in an empty folder with git initialised. Paste the prompt, let the agent build the first version, then play it yourself before asking for anything else. Send specific follow-ups ("the jump feels floaty") rather than "make it better". Time estimates are the author's guesses for an experienced engineer. Inference

1 · Dodge the blocks (one HTML file)

Teaches: the loop, delta time, keyboard input, rectangle collision and game states (page 7).

Build a small browser game in a single index.html file (inline JS and CSS, no libraries, no build step; it must work when opened from file://).

Game: the player is a square at the bottom of a 480x270 canvas, moving left/right with arrow keys or A/D. Blocks fall from the top at increasing speed. Touching a block ends the run. Score = seconds survived; keep the best score in localStorage.

Technical requirements:
- Fixed timestep update (1/120 s) with an accumulator; rendering once per requestAnimationFrame.
- A state machine with states: title, play, gameover. Space or Enter starts/restarts.
- Axis-aligned rectangle collision in a separate pure function.
- All tuning numbers (player speed, spawn rate, fall speed, speed-up per second) in one CONFIG object at the top.
- Canvas scales to fit the window with crisp pixels (image-rendering: pixelated).
- An F1 debug overlay showing FPS, entity count and hitboxes.
- Expose window.render_game_to_text() returning JSON with state, player x, score and block count.

Work independently; when done, list the CONFIG values and explain what each one changes.

Done when: it runs from a double-click; the speed is the same on a 60 Hz and a 120 Hz screen; you changed three CONFIG numbers and understood the effect.

Stretch: add a dash on Shift with a cooldown; add screen shake on game over.

2 · Platformer feel lab

Teaches: what makes a jump feel good, axis-separated tile collision, cameras (page 7, page 8).

Build a platformer "feel lab" as index.html + game.js (plain Canvas, no libraries, works from file://).

- 480x270 canvas scaled up with nearest-neighbour. Fixed timestep 1/120 s.
- A level defined as an array of strings ('#' solid, '.' empty, 'P' player start, 'C' coin, 'F' flag), about 3 screens wide.
- Player is a 12x16 rectangle. Kinematic movement (no physics engine): acceleration, friction on ground and in air, gravity, a higher gravity when falling, variable jump height (releasing jump early cuts upward speed), coyote time, jump buffering, max fall speed.
- Tile collision resolved on X first, then Y. Unit tests (plain JS, run with node) for: landing on a tile edge, hitting a ceiling, walking into a wall, falling at max speed onto a 1-tile floor.
- Camera follows the player with smoothing and a small look-ahead, clamped to level bounds.
- A side panel of HTML sliders bound live to every movement constant, plus a "copy settings as JSON" button and three presets: "floaty", "tight", "heavy".
- Debug overlay (F1): hitboxes, velocity, on-ground flag, coyote and buffer timers.
- Expose window.render_game_to_text() and window.advanceTime(ms) for automated tests.

Do not add enemies, art or sound yet.

Done when: you made your own preset that feels better than all three; you can explain coyote time and jump buffering; the unit tests pass.

Stretch: one-way platforms with tests; a walking enemy you can stomp.

3 · Skin and sound it (assets, licences, tests)

Teaches: swapping art without touching logic, procedural sound effects, credits, and agent-run tests (page 1, page 4, page 10, page 12).

First download Kenney Pixel Platformer (CC0) into assets/ yourself.

Extend the platformer in this folder:

1. Art: the Kenney Pixel Platformer pack is in assets/ (CC0). Read its tilemap image layout and draw tiles, player, coins and flag from it. Keep the old rectangle renderer and add a key (T) to toggle between "shapes" and "sprites" so game logic is untouched.
2. Sound: generate jump, coin, land and win sound effects in code with the Web Audio API (jsfxr-style parameters stored as data). Audio must start only after the first user input (browser autoplay rules). Add a mute key (M).
3. Credits: create CREDITS.md with a table (asset, author, source URL, licence, changes) and show the credits on a title-screen panel. Copy Kenney's License.txt next to the assets.
4. Tests: add Playwright tests that open the game, use window.advanceTime and window.render_game_to_text to (a) walk right for 2 seconds and assert x increased, (b) jump and assert the player left the ground and landed again, (c) fail on any console error, (d) take screenshots at 375x667 and 1280x720.
5. Add touch controls (left, right, jump buttons) shown only on touch devices.

From now on, record every asset or dependency you add in CREDITS.md and ask me before adding anything licensed GPL, AGPL, NC or ND.

Done when: both art modes work; sound plays after the first key press; the Playwright tests pass locally; the 375 px screenshot shows usable touch buttons.

Stretch: upload it to itch.io as an HTML5 game, fill in the AI disclosure honestly, and send the link to five people.

4 · Mini 3D racer

Teaches: a 3D scene, chase camera, arcade vehicle physics, checkpoints (page 9).

Build a small 3D racing game with Three.js. Use a pinned version of Three.js (vendor the file into lib/ so the game works offline); no other libraries; no model or texture files - everything procedural.

- Track: a closed Catmull-Rom spline from about 10 control points, turned into a flat road ribbon mesh 14 units wide with edge markers and a start line. Green ground plane, fog, hemisphere and directional light.
- Car: built from boxes and cylinders. Arcade controller (no physics engine): throttle, brake/reverse, drag, speed-dependent steering, and a "grip" factor that blends velocity toward the car's heading. Off-road (distance to spline > half width) caps speed lower.
- Chase camera with exponential smoothing in the fixed-step update; slight look-ahead; FOV widens a little with speed.
- Race logic: ordered checkpoints sampled along the spline (to stop corner cutting), lap counter, current and best lap time, R to reset to the last checkpoint.
- HUD: speed, lap, times. Touch buttons on phones. Pixel ratio capped at 2.
- Fixed timestep 1/120 s. Expose window.render_game_to_text() (position, speed, lap, checkpoint index, off-road flag) and window.advanceTime(ms).
- One AI car that steers toward a point 8 units ahead on the spline, with its own speed limit, using the same controller interface as the player.

Work independently. Afterwards, list every handling constant with a one-line description.

Done when: a lap takes 30–60 seconds; cutting a corner does not count a lap; the AI car finishes laps on its own; the camera does not jitter.

Stretch: replace the car with a model from the Kenney Car Kit (CC0, glTF), keeping its wheels as separate meshes that spin and steer.

5 · Rebuild in Godot through an MCP server

Teaches: how an agent works with an engine editor, plain-text scenes, headless tests and exports (page 5, page 10).

  1. Install Godot 4 (a single 86 MB zip for Windows) and do the first steps of the official "Your first 2D game" tutorial yourself, so you know the editor.
  2. Add a Godot MCP server to your agent, for example Coding-Solo/godot-mcp (6,130 ★, MIT): claude mcp add godot -- npx @coding-solo/godot-mcp, or the equivalent MCP entry in Cursor. Community servers are unvetted; read what tools a server exposes before you enable it.
  3. Install the GUT test addon.
Recreate the "Dodge the blocks" game (spec below) as a Godot 4 project in this folder, using GDScript (Godot 4 syntax only - no Godot 3 APIs such as KinematicBody2D or yield).

Spec: player square moves left/right at the bottom; blocks fall at increasing speed; touching one ends the run; score = seconds survived; best score saved to user://; states title / play / gameover.

- Use scenes: Main.tscn, Player.tscn (CharacterBody2D), Block.tscn (Area2D), HUD.tscn (CanvasLayer).
- Put all tuning values in an exported Resource (config.tres) so I can edit them in the inspector.
- Use the Godot MCP tools to create scenes, run the project and read debug output after each step; fix every error you see.
- Add GUT tests in res://test for the collision and scoring logic, runnable headless:
  godot --headless -s addons/gut/gut_cmdln.gd -gdir=res://test -gexit
- Add a Web export preset and a Windows Desktop export preset, and a README section explaining how to export from the command line.

Done when: the game runs from the editor; the GUT tests pass headless; you opened a .tscn file in a text editor and understood it; you produced a Windows build.

Stretch: port the platformer from project 2 using Godot's TileMap and an LDtk or Tiled importer; compare how much the agent could do without the MCP server.
