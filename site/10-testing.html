How agents test games

An agent that cannot see the game will happily report "fixed" for bugs that are still there. A game is a picture that changes 60 times a second, so ordinary web testing does not reach it. This page shows the testing ladder that works today, the hook pattern that makes a game readable to an agent, and what the benchmarks say agents still miss.

The core problem

A canvas or WebGL game is one opaque element. Accessibility snapshots, which browser agents rely on, see nothing inside it. Timing also makes runs flaky: the same keypress at a slightly different frame gives a different result. The fixes are to expose game state as text and to control time. Verified (Playwright MCP docs; OpenAI develop-web-game skill)

The hook pattern: make the game readable

OpenAI's develop-web-game skill turned a common practice into a contract: the game exposes two functions, and a bundled Playwright client uses them with screenshots and a console-error buffer. The skill was published at a pinned commit (82d2c5b4) and used for the Codex racer; on 2026-10-17 it was not on the main branch of openai/skills (the path returns 404), so check before you install it. Verified

// in the game: two hooks, no effect on normal play
window.render_game_to_text = () => JSON.stringify({
  mode: game.mode,                       // "title" | "play" | "dead" | "win"
  player: { x: Math.round(p.x), y: Math.round(p.y), onGround: p.onGround },
  coins: game.coins, enemiesAlive: game.enemies.filter(e => e.alive).length
});
window.advanceTime = (ms) => {           // step the fixed-timestep loop manually
  for (let t = 0; t < ms; t += STEP_MS) update(STEP_MS / 1000);
  render();
};
// in a Playwright test: deterministic, no sleeps
await page.keyboard.down("ArrowRight");
await page.evaluate(() => window.advanceTime(2000));
const s = JSON.parse(await page.evaluate(() => window.render_game_to_text()));
expect(s.player.x).toBeGreaterThan(200);
await page.screenshot({ path: "after-run.png" });

Illustrative code by the author; the function names follow the skill. The demos on this site expose a similar hook, window.__demoState[id].get(), which the site's own QA used to check that every demo moves, scores and finishes. Verified (our QA)

Agent testing in practice

  • Prefer the state hook over vision. Playwright MCP works from accessibility snapshots by default; a canvas has none. Vision mode (--caps=vision) adds coordinate clicks and screenshots, but models misread game images (lmgame-Bench lists "brittle vision perception" as a core failure). Verified
  • Run WebGL headed when captures look wrong. OpenAI's skill says: "If you suspect a headless/WebGL capture issue, rerun the Playwright script in headed mode." Verified. That headless Chromium has no WebGPU adapter comes from one project's notes. Unverified as a general rule.
  • Watch the idle timeout. A headless browser started by Playwright MCP closes after one hour idle by default (--idle-timeout, 0 disables), because animated pages burn CPU. Verified
  • Test on several viewports. Simon Willison's agent-built game passed smoke tests on three viewports, but he still found two phone bugs by hand: the canvas rendered at 2× size, and win-screen CSS swallowed taps. Verified
  • Ready-made skill kits bundle the stack, the test contract and guard-rails: awesome-gamedev-agent-skills (1,572 ★, 74 skills), game-creator (345 ★, includes a game-qa skill for Playwright gameplay, visual regression and accessibility), phaser4-gamedev (29 ★, a hook blocks deprecated Phaser 3 APIs). What this means for you

Agents solve about half of realistic game-dev tasks and find about half of real bugs. Seeing the game helps but does not close the gap, and reading the code alone over-credits missing features. Plan to playtest every build yourself; let the agent own rungs 1 to 6 and you own rung 7. Note that the models in these papers are from the first half of 2026 and newer models may score higher. Inference

A minimal test plan for your first game

  1. Keep logic out of the renderer; ask the agent for unit tests of collision and scoring from day one.
  2. Add the two hooks and a seeded random generator.
  3. One Playwright smoke test per level: load, play a scripted input list with advanceTime, assert the state, screenshot at 375 px and 1280 px wide, fail on any console error.
  4. Add the stats.js overlay during development; check frame time on your weakest device.
  5. Every evening: play it yourself for ten minutes and write down what felt wrong. Feed that list to the agent.
