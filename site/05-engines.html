Engines and libraries, judged for agent use

Which engine an agent can work with well depends on things that rarely appear in engine comparisons: whether the project is plain text, whether it builds from the command line, whether the model knows the current API, and whether there is an MCP server. This page compares the main options on those terms, with dated popularity numbers. The sortable explorer has every entry with more columns.

What makes an engine agent-friendly

Text files

The agent edits code and scene files directly and you review diffs. Web libraries and Godot (.tscn, .gd) are text; Unreal's .uasset files are binary.

Headless run and build

The agent can start the game, run tests and export without clicking: npm run build, godot --headless --export-release, Unity -batchmode.

Model knowledge

Lots of public code helps, but fast-moving APIs hurt: models still write Phaser 3 code for Phaser 4, Godot 3 code for Godot 4, and outdated Bevy.

Editor bridge (MCP)

For editor-centric engines, an MCP server lets the agent inspect scenes, run play mode and read logs instead of guessing.

A good split of work: you draw levels in Tiled or LDtk (level design needs a human eye), the agent writes the loader, collision and entity spawning, and a validator that checks every level is reachable with the actual jump physics. Inference

So "which engine is most popular" has no single answer: Godot leads among hobbyists and jams, Unity among shipped Steam games, Unreal among large studios. For an engineer making a first game with an agent, the more relevant facts are text projects, headless builds and price. Inference
