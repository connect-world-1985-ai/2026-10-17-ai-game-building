AI images for sprites, tiles and textures

Generating one nice picture is easy. Generating forty frames of the same character, on a transparent background, aligned to a pixel grid, in a consistent style, is not. This page lists the services an agent can call in October 2026, then goes through the four problems everyone who ships AI sprites runs into, and the fixes that work.

Model names change fast

Names and prices below are what vendor pages said on 2026-10-17 (for example gpt-image-2.5-sunburst, gemini-nano-banana-2.1, FLUX 3 Image). Your agent's training data may know older names. Point the agent at the vendor docs page instead of trusting its memory.

The four hard problems

1. Transparent backgrounds

Game sprites need an alpha channel so the background shows through. Ask a model without alpha support for a "transparent background" and it paints a checkerboard or a flat colour as pixels. Robotic Ape's write-up on Nano Banana Pro sums up the trap: "You cannot cleanly remove a background that shares color space with your sprite content (black bg + black outlines = unsolvable). And anti-aliasing permanently bakes background color into edges." Robotic Ape, 2026-03-07 Practice

ApproachHowNotes
Native alphaOpenAI background:"transparent"; Ideogram transparent mode; PixelLab; Recraft vectorBest when available. Still check the file: alpha channel present and minimum alpha below 255. Verified

Always look at sprites over several backgrounds. As the dog-game author put it, "Those moody, dim backdrops look gorgeous, and they lie to you." Practice

2. Consistency and animation frames

This is the biggest problem. OpenAI's own documentation lists it as a limitation: the model "may occasionally struggle to maintain visual consistency for recurring characters or brand elements across multiple generations." OpenAI image guide Verified

Generating each animation frame separately makes hair colour, clothing, proportions and foot placement change from frame to frame. Reports agree across independent sources: changeinmotion.tech, Layr Kits, and a dev.to author who "gave up on AI characters" and switched to CC0 hand-drawn sprites while keeping AI for code. dev.to Practice

Game-specific animation tools

PixelLab's skeleton animation "moves the character instead of redrawing it each frame". Retro Diffusion and Ludo.ai offer animation from one image. Best first stop. Verified

Video, then frames

Generate a short clip of the character on a green background with an image-to-video model, extract frames with ffmpeg, then key and pack. "Consistency beats resolution." Practice

Row-per-state skills

One base image, one row per animation state, deterministic extraction into an atlas. Open-source agent skills: sprite-gen, agent-sprite-forge. Verified

Train a style

Scenario trains a character model from 5–15 images or a style model from 10–30, usually in 30–60 minutes. Useful for hundreds of assets in one style. Verified

Even with these, a human still curates frames. Agents cannot reliably see subtle jitter in screenshots, so give them numeric checks (palette count, bounding-box drift per frame) instead of asking "does it look right?" Inference

3. Pixel grid and palette

General models produce "fake pixel art": blocks of uneven size and thousands of colours. Two fixes: use a pixel-native generator (PixelLab, Retro Diffusion) that outputs at true low resolution, or run a snapping tool, then scale up with nearest-neighbour only.

4. Slicing, packing and textures

Once frames are clean, packing them into an atlas is ordinary scripting (Pillow, ImageMagick) or a packer such as Free Texture Packer (MIT, last updated 2024) or TexturePacker ($49.99). Keep the same cell size and order the engine expects. Verified

Tileable textures: none of the general image models documents a guaranteed seamless mode. Generate, then make the image seamless in post (offset and blend edges), or use CC0 PBR textures from Poly Haven or ambientCG. Unverified that any hosted general model guarantees tiling.

What the model draws without an image model

Recap of page 1 with the evidence: frontier models write good SVG icons; the informal "pelican riding a bicycle" test is now saturated, and its creator, Simon Willison, says the correlation with model quality is "mostly severed". Willison's tag page, HF OpenEnv Verified. Academic benchmarks such as SVGenius find all models degrade as drawings get more complex. Verified. Pixel Art Bench (24×24 grids written as text) shows the task works but that fine-tuning "fails to produce meaningful improvements in pixel art quality". Practice

Takeaway: code-drawn SVG and Canvas art is genuinely usable for UI, icons and minimalist games. It is not evidence that a language model can draw consistent animated characters. Inference

A pipeline that works today

  1. Decide the style first. Write a one-paragraph style guide (palette, outline, perspective, resolution). Generate a reference sheet and pick one.
  2. Pick the right tool per asset type. Pixel characters: PixelLab or Retro Diffusion. Icons and UI: Recraft SVG or code. Backgrounds and title art: GPT Image or Nano Banana.
  3. Script it. Ask the agent for tools/gen_assets.py that reads a JSON list of assets with prompts and seeds, prices the batch first, and writes files plus a manifest.
  4. Post-process deterministically. Background removal, grid snap, palette lock, trim, anchor at the feet, pack.
  5. Verify with numbers and with your eyes. Alpha present, palette size, frame bounding boxes. Then look at a contact sheet on light and dark backgrounds.
  6. Record provenance. Tool, plan, date, prompt and licence terms in CREDITS.md (see page 12).
